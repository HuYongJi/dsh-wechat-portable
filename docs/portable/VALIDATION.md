# 验证记录与待验收项

## 版本与边界

- 独立分支：0.1.0-alpha.8，基线为上游 v0.9.1。
- 目标：DSH 0.2.0-rc.2；不宣称兼容其他 SDK 版本。
- 本地环境：Windows、Node 24.21.0、pnpm 11.7.0。
- alpha.1 已获用户授权安装到本机桌面。用户截图确认面板可渲染，但报告 `cannot get property "remote.wechatPortableControl" without inject`；不能将此前离线测试视为桌面端到端通过。
- alpha.2 修复：先挂载贡献，再在注入 `remote.wechatPortableControl` 的子上下文中创建控制器和面板；不能直接把依赖加到负责挂载的入口，否则会等待自己提供的服务。卸载先销毁面板消费者，再撤销贡献。
- 新回归使用真实 Cordis 插件 fiber：旧写法复现同样报错，修复后状态/模拟扫码调用以及卸载/重新挂载通过。此前普通对象 mock 缺少框架依赖检查，是测试遗漏。
- alpha.2 用户截图已确认原生状态读取成功。默认目录不存在的问题经本机创建专用目录解除。
- alpha.3 已进行一次真实取码请求及内存 PNG 生成验证：严格 TLS、320×320 PNG、原生响应校验通过；没有输出/保存二维码或标识，没有轮询、手机确认、账号保存、启动桥接或模型请求。更新后的实际界面仍须由用户重启确认。
- 扫码请求使用私有 HTTPS Agent 和逐请求 `rejectUnauthorized: true`，不改进程环境或全局 Agent。即使继承环境为 `NODE_TLS_REJECT_UNAUTHORIZED=0`，仍拒绝不可信证书和主机名不匹配。此变量的全局不安全设置并未因此被修复，应由设备使用者另行核对。
- 协议对照 [腾讯当前参考实现](https://raw.githubusercontent.com/Tencent/openclaw-weixin/main/src/auth/login-qr.ts)：新绑定 POST 空 token 列表、允许成功响应省略 ret、状态请求最多 35 秒。绝不枚举或发送其他账号 token。
- 额外手机配对码、登录节点重定向、已有绑定等分支明确返回固定提示，不再无限等待；本版尚未实现额外配对码交互或跨节点轮询，不宣称这些分支可用。
- 授权写入前校验当前请求和 Host 生命周期；过期/已卸载请求不落盘。新保存服务地址仅允许 HTTPS 的 weixin.qq.com 域，拒绝用户信息、端口、查询及外部域。

## alpha.4 消息初始化修复

用户确认 alpha.3 已绑定，手机发消息能收到桥接错误提示。定向日志定位为 `cannot get property "agentPresets" without inject`。Host 插件的 inject 声明不会自动成为 AgentSetup 回调上下文的依赖 API；同一流程中的 tools 属性访问也存在相同问题。

改用 Cordis 正式的上下文 `get()` API 获取 active 服务，保留 Agent 调用者作用域并对缺失服务显式失败；不修改权限策略、不改全局服务、不重新绑定。新增回归使用真实 Cordis 的独立 provider fiber、真实 scope，以及实际 SDK ToolsService：旧属性访问分别复现两种报错，修复后完整 setup 通过；工具限制只作用于该 Agent，其他 Agent 与全局不受影响，销毁后限制注销。新建保留更严格默认值，恢复不改已存 preset/权限，缺失或错误 preset 不回退。

测试中的 preset 存储和 session 是内存替身，没有调用真实模型、读取聊天或发送微信测试消息；正常模型回复仍需用户升级重启后验收。

## alpha.5 对话内会话管理

新增 `/new`、`/sessions`、`/switch`、`/clear` 与固定中文短语；仍保留旧命令别名。创建/清空/切换直接操作真实 Host 会话控制，微信切换不会自重启 daemon，成功提示在 Host 确认后发送。

自动化测试使用临时独立数据目录和合成账号，不读取个人 profile、聊天记录，不调用模型或微信。覆盖命令解析和误触发、列表编号快照、ID/名称歧义、当前标记、失败回滚、owner 隔离、长列表分段、排队取消与旧流收尾。实际 Host 内部 HTTP 处理器通过内存 HTTP/SDK 替身执行，验证旧 bot 级与 owner 复合 key 的清除、新建写入与切换恢复；不把替身验证等同于真实 DSH/微信端到端通过。

源码构建不自动安装或热替换已安装插件；尚未发送真实微信测试消息，也未重启用户正在使用的桥接。

## alpha.6 微信专用回复排版

排版仅作用于 daemon 的完整已提交助手消息，先生成微信纯文本视图，再攒批/分段；Host 事件、客户端渲染、输入提示词与历史 Markdown 不改。管理命令、审批和主动通知保持原行为。旧待补发内容不猜测格式、不二次转换。

新增 16 项隔离回归：覆盖标题、强调、列表/任务、引用、链接与本地路径、纵向表格、代码/空行、超长回复、组合 emoji、1200/4000 边界；通过真实消息处理入口断言发送副本已排版而冻结的源事件和存储内容不变。补发覆盖部分成功、发送期间新消息边界、持久化/重建、重叠触发、同时追加和 owner 隔离。额外覆盖包含空格/反引号的路径、代码中的反斜杠/竖线、缩进代码和跨行行内代码，避免排版改变技术内容。

只使用合成消息、模拟发送器和临时独立目录，未读取真实聊天、发送微信消息或重启正在使用的桥接。构建不等于已安装版本生效，仍需更新插件后由使用者进行真实手机/客户端对照验收。

## alpha.7 客户端会话标题

已对照安装的 DSH 0.2.0-rc.2 客户端及 Host 列表实现：读取 `title` 投影，不把项目名或消息正文冒充会话标题。活跃会话使用精确 Session 对象的 `sessionProjections.cachedSnapshot()`；历史会话先使用 `sessionPersistence.list()` 的完整 header，再读取 `sessionProjectionCache.cachedSnapshot()` 或仅在快照缺失时使用 `cachedPredecessorTitle()`。不强制折叠历史，也不新建/恢复 Agent、生成/重命名标题或改写缓存。未命名/不可读行仍可按序号和 ID 选择。

新增 11 项回归：包括真实 SDK 投影注册表的缓存读取、标题变化与卸载，实际 Host HTTP 接线的实时/历史优先级、元数据查询期间恢复会话的竞态、状态与工具 schema，中文/emoji/控制字符/长标题，以及重名拒绝和编号稳定性。只使用合成记录和临时目录，未读取真实会话正文、调用模型或向微信发测试消息；真实客户端与手机标题对照仍待更新安装后验收。

## alpha.8 干净检出与发布修复

Alpha.7 首次 GitHub CI 发现两个公开合成 TLS PEM 夹具被通用忽略规则排除；本地已存在这些文件，因此此前本地通过不能代表远程干净检出通过。Alpha.8 仅对这两个已核验为 self-signed localhost 的测试文件添加精确路径例外，仍不将其打入插件安装包，也不更改系统信任或生产 TLS 设置。新增回归校验证书、密钥、忽略规则与安装包排除约定；后续版本发布前需要验证干净源码副本，GitHub CI 与真实桌面/微信验收仍须分别判断。

## 已验证的自动化范围

Alpha.7 阶段的一次 Windows 本地验证记录（不等同于其后来失败的干净 CI）：构建、类型检查、14 个测试文件共 176 项检查（137 项 Node test 检查，含隔离 TLS 子进程中的 6 项；另有 39 项继承断言）、exports 与客户端产物检查、`git diff --check`。其中会话管理新增 21 项，分为命令/队列/消息入口和实际 Host 接线两组隔离回归。新增真实本地 HTTPS 测试覆盖不可信证书、可信测试 CA、主机名校验、重定向拒绝、完整请求期限、64 KiB 边界与提前断开。测试证书/密钥为公开合成夹具，仅在测试子进程受信，不修改系统证书库，不进入安装包。

Windows 测试发现普通 `realpathSync` 和 `lstat().isSymbolicLink()` 未能识别一种 Junction，已改用 `realpathSync.native` 的最终路径进行边界验证；对应回归已通过，不是跳过测试。

另外用实际安装桌面提取出的 0.2 Host artifact 验证函数检查本包 TYPERT，并用已发布 0.2 strict registry 验证注册/撤销。确认 `./typert` 由宿主 typert-loader 管理，移除了会与其异步扫描竞争的手动重复注册；描述符补齐了真实 loader 必须的 `tags`。读取实际 connection 实现确认 operator peer 由宿主创建并传入调用上下文。这些属于**离线契约验证，不是桌面 IPC 端到端验证**。

alpha.2 另外将实际桌面 Gateway Client bundle、已发布 strict registry、真实 Cordis 和本包构建后的 Client 放在内存测试环境中连通。状态与模拟二维码调用、卸载与再次挂载均通过；Connection 和槽位为内存替身，未连接正式 Host 或微信。此测试验证真实 namespace 注入与 wire 参数映射，仍不等于 GUI/扫码端到端验收。

默认 `node --test` 曾触发 Windows 沙箱的捕获式子进程管道限制。项目测试脚本改为逐文件独立进程并继承 stdio；没有提升权限、放宽文件边界或跳过用例。

## 发包检查

发布前执行 `pnpm run verify`，重新构建 Host/Client、运行测试、核对 exports、浏览器 bundle 注册标识、生成文件允许列表。tarball 另做文件清单/私密哨兵/个人绝对路径审计，并在包含中文和空格的新目录解包执行配置 CLI；结果随分发校验和与审计报告交付。

## 必须由使用者完成的真实验收

- [ ] 在隔离/测试 DSH profile 安装，重启后设置面板正常加载；禁用/再启用没有重复 Remote 注册。
- [ ] 重新扫码，确认后不自动启动；手动启动后手机发短文本，收到单轮完整回复。
- [ ] 多条消息顺序正常；快速空回复、失败、取消都能终止等待并有可理解提示。
- [ ] 连续对话与宿主重启后恢复上下文；更换 preset 默认值不改变已保存会话的 preset/权限。
- [ ] 创建尚未完成时立即 `/stop`、`/new`；不应在停止后又开始执行旧请求。
- [ ] 微信发送“新建会话”后立即“查看会话列表”，能看到新会话及当前标记；“切换会话 2”继续目标上下文，桥接不自重启。
- [ ] 同项目的不同会话展示各自客户端标题；电脑端手动重命名后再次查看列表、当前会话可见新标题；关闭/重启后历史标题仍可展示，重名要求序号/ID，无标题不伪装成项目名。
- [ ] 同项目多个会话时按序号/唯一短 ID 切换正确；同名和已打开会话给出明确提示，列表发送失败时不使用错误编号。
- [ ] “清空上下文”后模型不再继承旧对话；工作目录/模型偏好保留，DSH 历史未删除，重启桥接不会复活已清空绑定。
- [ ] 在模型输出、工具慢取消、微信发送限流期间执行 `/stop`、`/new`、`/clear`；停止及时送达，旧回复/收尾不污染新会话，停止确认后可接收下一条任务。
- [ ] 同一回复包含标题、列表、表格、代码和带空格路径时，微信排版清晰，电脑端仍为原始 Markdown；超长回复顺序、代码复制与断网补发符合预期。
- [ ] 产生安全测试审批，错码/旧码/超时拒绝；正确码只批准这一次。严格 never 策略不被覆盖。
- [ ] 非绑定本人不能对话、调用命令或审批。
- [ ] 用无敏感信息的 PNG、PDF、DOCX、MP4 测收发；核对 25 MiB 限制和目录约束。文件下载成功不等于模型理解了内容。
- [ ] 导出偏好到第二台设备；本机路径、授权、历史均不出现；重新选择工作目录、模型与扫码后可运行。
- [ ] 正常退出、宿主崩溃与重启的守护进程状态；不错误终止其他进程。
- [ ] macOS 与 Linux 真机分别验证构建、安装、运行、文件权限、进程停止。

回复使用已提交的 assistant/message 文本攒批发送；不转发可能被重试撤回的 live attempt。网络中断不提供严格 exactly-once 保证；已发送的消息或已完成的文件写入不会因取消而回滚。单次回复连接最多等待 30 分钟，超时不假装宿主任务已停止，可在手机 `/stop` 或电脑端检查。

在以上真人验收完成前，保持 alpha 标签，不宣称生产可用、三平台全面通过或真实微信媒体已验证。
