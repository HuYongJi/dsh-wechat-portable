# DSH WeChat Portable · 0.1.0-alpha.8

面向 **DSH Desktop 0.2.0-rc.2** 的独立社区微信桥接预览版。基于 lanbaolu/dsh-wechat-bridge 0.9.1（MIT）改造；不是 DeepSeek、微信或上游作者的官方产品，也不代表获得其背书。

> **预览版，先用测试账号和独立工作目录。** 本地构建、自动化与协议边界测试不能替代桌面安装和真实微信验收。alpha.1 本机安装后发现原生 Remote 的依赖注入遗漏；alpha.2 针对该问题修复并增加真实 Cordis 生命周期回归。alpha.3 改为独立严格 TLS 的扫码请求并兼容当前二维码响应；真实取码与 PNG 生成已通过，用户已确认绑定成功，微信收发通道能返回错误提示。alpha.4 修复 Agent 初始化中两处作用域服务访问错误；alpha.5 新增对话内会话管理命令与中文短语，修复取消、切换和上下文清理的并发边界；alpha.6 新增微信专用回复排版，客户端与原始历史不变；alpha.7 的会话列表改用客户端会话标题，支持按唯一标题切换。真实微信会话管理、正常模型回复、macOS/Linux 与媒体收发仍待验证。若微信要求额外配对码或切换登录节点，本版会明确停止，尚不支持这些分支；不要在聊天中发送验证码。使用相关微信接口可能受服务规则、接口变更和账号风控影响。

## 这一版的重点

- 使用实际 0.2 SDK，不做版本豁免、不降级宿主。
- 桌面设置面板走原生 Typert Remote/IPC，不依赖 `file://` 页面跨域调用 HTTP。
- 单个扫码绑定者本人使用；不开放多用户、bootstrap 或远程添加信任。
- 独立 profile 数据目录；新建会话保留更严格的权限默认值，恢复会话不覆盖已有权限或 preset。
- 微信文本批量回传、会话恢复、停止、一次性审批码；快速结束事件有有界重放。
- 分享程序与普通偏好，不分享微信凭据、账号标识、聊天记录、日志、二维码、进程状态或本机路径。
- 图片/文件/MP4 下载采用随机私有文件名、25 MiB 单文件上限与有界流读取；附件缓存上限 256 MiB。
- **不自动上传回复中提到的文件。** 只有本人显式 `/send`，且文件必须在当前工作目录内、非隐藏、非私密目录、非链接且类型受支持。

## 在 DSH 插件页粘贴链接安装

1. 确认 DSH 为 **0.2.0-rc.2**。其他版本不宣称兼容；不要添加版本豁免。
2. 保留当前 DSH 配置备份，并停止旧微信桥接。不要让两个桥接同时轮询同一账号。
3. 打开 [GitHub Releases](https://github.com/HuYongJi/dsh-wechat-portable/releases)，选择要安装的版本，复制发布说明中的安装直链，或 **Assets 中 `.tgz` 文件的下载链接**。
4. 在 **DSH → 插件 → 添加插件 → 包名或地址** 中粘贴完整链接，确认来源可信后安装。不要填仓库主页、Release 页面地址或自动生成的 Source code ZIP。
5. 安装后启用插件，**完全退出并重新打开 DSH**。不会自动开始微信绑定；默认 `autoStart: false`。
6. 设置中打开“微信桥接（Portable）”，选择一个**本机已存在、专用的工作目录**，获取二维码并在微信确认。
7. 扫码成功后仍保持停止；检查模型选择与工作目录，再手动启动。

Alpha.8 发布后的固定安装地址如下；**只有对应 Release 发布成功后才可用**，请先确认 Releases 中存在该附件。预览版不使用 `releases/latest`，避免跳到其他版本：

```text
https://github.com/HuYongJi/dsh-wechat-portable/releases/download/v0.1.0-alpha.8/dsh-wechat-portable-0.1.0-alpha.8.tgz
```

安装包已包含编译后的 Host/Client 和二维码运行依赖，使用者无需克隆仓库、安装开发依赖或编译源码。**这不等于仓库主页地址的源码安装已通过验证。**

若 DSH 无法访问 GitHub，手动下载 `.tgz` 和同一 Release 的 `SHA256SUMS.txt`，核对 SHA-256 后，在同一输入框填写安装包的**本地绝对路径**。更换 npm 镜像不能替代访问 GitHub；不要关闭 TLS 校验。若已安装旧版，先停止桥接并备份，再按插件页提示卸载旧版、安装新版；不要删除私有数据目录，同设备保留原绑定时无须重新扫码。

安装会改变目标设备的插件配置，必须由该设备使用者自行确认。本项目不内置下载/安装宿主、提权、写注册表、修改 ACL、后台服务或开机启动脚本。维护者发布步骤见 [Release 分发指南](docs/portable/RELEASING.md)。

## 微信使用

| 操作 | 命令/方式 |
|---|---|
| 对话 | 直接发文字；使用 DSH 当前配置的模型 |
| 停止当前任务 | `/stop` 或“停止当前任务” |
| 创建并进入新会话 | `/new` 或“新建会话”“创建新会话” |
| 查看会话列表 | `/sessions` 或“查看会话列表”“会话列表” |
| 切换已有会话 | `/switch <序号或ID>` 或“切换会话 2”“切换到第 2 个会话” |
| 查看当前会话 | `/session` 或“当前会话” |
| 清空上下文 | `/clear` 或“清空上下文”“清除上下文” |
| 查看帮助 | `/help` 或“会话帮助” |
| 批准一次权限请求 | 完整回复消息中的 `/yes <审批码>` |
| 拒绝权限请求 | `/no <审批码>` |
| 发送成果文件 | `/send ./report.pdf` |

### 会话管理说明

- `/new` **立即创建**空白 DSH 会话并进入，保留当前工作目录与模型设置；旧会话仍可在列表中切回。需要已配置可用的 DSH 模型和工作目录。
- `/sessions` 列出当前 profile 的项目会话，首行显示**客户端会话标题**，第二行仅显示项目名与短 ID；标记“当前”和“已打开”，不再把完整目录路径挤在标题旁边。没有可用标题时显示“未命名会话”。`/sessionlist`、`/projects` 是兼容别名。数字选择固定对应**最近一次显示的列表**，不会因新增会话或重命名而选错；失效时提示刷新。
- `/switch` 支持序号、完整 ID、至少 4 位的唯一 ID 前/后缀、唯一会话标题，并兼容项目名或路径。精确标题优先于项目名；重名时要求明确选择，不默认选第一项。数字、命令保留字或已省略的长标题建议用列表序号/ID 选择。`/session <目标>` 仍可使用；`/session off` 解除绑定。
- 标题来自 DSH 客户端使用的同一标题投影；重新发送 `/sessions` 或 `/session` 会重新读取，不单独缓存或改写标题。历史会话使用宿主已有的标题缓存，可能落后于最新保存；缺少缓存时不扫描聊天记录、不恢复 Agent，也不调用模型生成标题。标题展示改进从 alpha.7 开始提供，需要更新安装包并完整重启 DSH 后生效。
- 切换继续目标会话的 DSH 上下文，无需重启桥接。电脑端仍打开的其他会话须先关闭，再从微信切换，避免两个 Agent 同时占用。
- `/clear` 清掉桥接近期记录和当前绑定，下条消息使用全新上下文；**不会删除 DSH 已保存的历史，也不删除工作文件**。工作目录和模型偏好不变，`/reset` 另将会话偏好恢复为桥接默认值。新建/恢复仍遵守现有权限与 preset 规则。
- 新建、清空、切换、重置与停止命令会中断当前任务并丢弃排队消息；先等旧任务清理完成，再操作新会话。已完成的工具副作用和已发出的微信消息不能撤回。查询命令按消息顺序处理，长任务中可先 `/stop` 再查看列表。
- 短语只匹配整条明确指令，可带一个句末 `。！？!?`；引用、代码块和“请解释如何清空上下文”等普通讨论不会被当作管理命令。微信语音转写也按相同规则处理。只允许扫码绑定者本人操作。
- `/history` 是桥接的近期显示记录，不是 DSH 完整历史浏览器；切换后该显示记录重新开始，但目标 DSH 模型上下文会恢复。

以上能力从 alpha.5 开始提供。升级后应完全退出并重新打开 DSH，再启动桥接，使 Host 与 daemon 使用同一版本；仅刷新页面或单独重启旧 Host 下的 daemon 不足以完成升级。保留原数据目录时不需要重新扫码。真实微信与桌面端到端验收见 [验证记录](docs/portable/VALIDATION.md)。

不带审批码、过期、错误或上一条请求的审批码均不能批准新请求。超时、断开、取消、推送失败时不授予权限。需要信息时 Agent 以普通文字提问，不使用手机不可见的交互表单。

支持显式发送的类型：PNG/JPEG/GIF/WebP、PDF、DOCX/XLSX/PPTX、TXT/MD/CSV、MP4。没有病毒扫描或安全内容识别；普通文档也可能包含敏感信息，发送前自行检查。语音只保留上游接口返回的转写文本，不提供语音合成。视频的实际理解能力取决于宿主工具/模型，不能因下载成功就宣称可理解。

### 微信专用回复排版（alpha.6）

仅在 daemon 向微信发送**助手回复**时生成纯文本副本；不修改模型提示词、Host 事件、DSH 客户端渲染或保存的 Markdown 历史。

- 标题显示为 `【标题】`；去掉正文粗体/斜体标记；列表使用 `•`，任务使用 `☐ / ☑`。
- Markdown 表格转为纵向“字段：值”，避免手机窄屏横向挤压；链接保留说明和完整网址/路径。
- 代码块使用 `【代码 · 语言】` 标签，保留代码符号、缩进与空行；行内代码仅去掉外围反引号。
- 完整消息先排版，再按原阈值/定时器攒批并分段；单条仍不超过 4000 个 UTF-16 单位，尽量不切开 emoji 或组合字符。不逐 token 刷屏。
- 补发使用已排版文本，不重复处理代码，也不重发已确认成功的分段。网络超时或崩溃仍不保证严格 exactly-once；旧待补发内容保持原样。
- 管理命令（含 `/history` 的原始记录）、权限审批、主动通知、附件与用户输入保持原有行为。不执行 HTML，不下载链接或图片；未识别的 Markdown 尽量原样保留。

例如：

```text
【处理结果】

• 微信：更易读
• 客户端：保持原样

1. 项目：排版
   状态：已完成
```

源码构建不会自动替换已安装插件。更新安装包后，完全退出并重新打开 DSH，再启动桥接即可生效；仅刷新客户端页面不会更新正在运行的 daemon。

## 迁移到另一台设备 / 分享给别人

**只分享安装包、源码包和可选的偏好导出文件；绝不要复制整个私有数据目录。**

安装包与平台无关，但目标设备仍须自行安装兼容 DSH；这不是包含 DSH、Node、模型和账号授权的“一键绿色版”。

默认状态位置：`DSH_PROFILE_DIR/wechat-portable`；未设置该变量时为 `DSH_HOME/profiles/<profile>/wechat-portable`（`DSH_HOME` 默认为用户目录下的 `.dsh`）。可使用插件的绝对本地 `dataDir`，但它是本机配置，不在导出内容内。不同 profile 与原版数据目录隔离。

配置工具不会安装、启动 DSH 或申请权限。已安装包可以运行 `dsh-wechat-portable`；源码构建后也可直接使用：

```text
node lib/portable/cli.js doctor --profile desktop
node lib/portable/cli.js export ./wechat-settings.json --profile desktop
node lib/portable/cli.js import ./wechat-settings.json --profile desktop --workspace "本机已有工作目录的绝对路径"
node lib/portable/cli.js import ./wechat-settings.json --profile desktop --workspace "本机已有工作目录的绝对路径" --confirm
```

- 使用自定义存储位置时，追加 `--data-dir "绝对本地目录"`。
- 导入默认只预览；停止桥接后才可用 `--confirm` 写入。
- 白名单只有用量尾注、拒绝通知和安抚消息的布尔/数值设置；不包括自由文本、提示词、模型、路径、权限、信任集或账号。
- 新设备重新选择工作目录和 DSH 模型，**重新扫码**。不会迁移聊天上下文；原设备的凭据也不会因此自动撤销，请单独停止/解绑旧设备。
- 导出文件不得覆盖已有文件，也不得写进私有状态目录。未知版本、额外字段、非法类型、超大 JSON、路径/凭据/权限注入均被拒绝。

更详细的边界与验收见 [安装和迁移](docs/portable/INSTALL-MIGRATE.md)、[验证记录](docs/portable/VALIDATION.md)。

## 从源码构建

需要 Node **22.19+**（本机使用 24.21.0）及 **pnpm 11.7.0**。宿主 SDK 是开发期依赖；不是硬编码的另一份个人 DSH 源码。使用已提交的 pnpm 锁文件，不使用上游旧 npm 锁文件。

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm run verify
```

生成可分发的 Release 附件（会重新验证一次，不执行任何远程发布）：

```text
pnpm run release:pack
```

产物位于 `dist/release/`，包含 `.tgz`、SHA-256、安装直链、文件清单和发布说明。目录必须为空；重复验证请使用新的 `--out-dir dist/其他目录`，脚本不会覆盖已有包。推送与包版本一致的 `v版本号` tag 后，GitHub Actions 才会创建对应 Release，详见 [发布指南](docs/portable/RELEASING.md)。

构建/测试脚本只使用 Node，支持含空格和非 ASCII 的路径，不调用 Bash、不创建宿主源码软链接、不读取开发者个人 profile。测试子进程继承标准输入输出，以适应 Windows DSH 沙箱的管道限制。

运行时二维码依赖连同其许可证打入 tarball；DSH SDK 是由兼容宿主提供的 peer。离线使用仍需要已安装的 DSH 及其依赖；微信/模型连接需要网络。首次源码安装与构建依赖下载也需要网络，不宣称完整离线运行。

## 隐私与卸载

- Linux/macOS 创建私有目录 0700、文件 0600；Windows 依赖当前用户目录继承的 ACL，**不会自动更改系统 ACL**。不要把状态放在共享盘、公共目录或多人可读位置。
- 调试日志默认关闭；即使经过脱敏，日志、附件和会话仍是私密数据，不应公开上传。普通运行日志保留约 30 个日期文件。
- 停止桥接、禁用/卸载插件即可停止接入。数据不自动删除，以免误删；解绑及数据清理必须由使用者自行核实后操作。
- 本地管理端口只绑定回环地址；HTTP 面板另有同源/方法/自定义头限制。它们不是供公网或局域网开放的远程管理 API。
